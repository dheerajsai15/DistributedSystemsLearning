Section 2 · What Redis is

A server that holds keys in memory and runs one command at a time

Redis is a key-value store. Each key has a name and a value, and the value has a type. This project uses two types: a string for the counter and a list for the posts. Clients send commands over TCP (port 6379). Redis puts the commands in a line and runs them one at a time, so two commands never run at the same moment.

INCR adds 1 and returns the new number. If the key does not exist, Redis starts from 0. LPUSH adds an item at the left end. LRANGE posts 0 -1 returns all items from index 0 to the last one (-1 means "the last"). So the newest post comes first. All values are stored as text: GET returns "3", not 3.

Section 4 · Leader and follower (Part 3 preview)

The follower copies the leader's stream of writes

The leader runs each write, then sends the same command to the follower. Each node counts the bytes of the stream that it has processed. This number is the replication offset. If the offsets are equal, the follower is up to date. The leader also keeps the most recent writes in a fixed-size backlog. In this demo, the backlog holds 4 writes. In Redis, the default size is 1 MB.

Replication lag: the time between "the leader has the write" and "the follower has the write". In that time, a read from the follower returns old data. When the link comes back, the follower sends its offset. If the missing writes are still in the backlog, the leader sends only those (partial resync). If they are not, the leader sends a full snapshot (full resync).
Section 5 · The ioredis API you need

One client object, one method for each command

ioredis gives you a Redis class. Each instance holds one TCP connection to one Redis server. Each Redis command is a method with the same name in lowercase. Each method returns a Promise, so you use await in an async handler.

import Redis from "ioredis";

// Make it at module level: one connection for each process, shared by all requests.
const leader = new Redis({
  host: process.env.REDIS_LEADER_HOST ?? "redis",
  port: 6379,
  enableOfflineQueue: false,  // no connection? fail now, do not queue
  maxRetriesPerRequest: 1,     // retry a command one time only
  commandTimeout: 1000,        // no reply in 1 s? fail
});

leader.on("error", (err) => console.error("redis:", err.message));
Add the "error" listener. Without it, ioredis prints "Unhandled error event" again and again while Redis is down. The listener only logs. Each failed command still rejects its own Promise, so use try/catch in the handler and send an HTTP error (for example 503).

The methods for this project

await client.incr("counter")
Returns number: the new value. Part 2
await client.get("counter")
Returns string | null. null means the key does not exist. Optional, for checks.
await client.lpush("posts", text)
Returns number: the new length of the list. Part 3
await client.lrange("posts", 0, -1)
Returns string[]: all items, newest first. Part 3
client.on("error", fn)
Called on connection errors. Also useful: "connect", "ready", "close".
Part 3: you make two clients, one to REDIS_LEADER_HOST for writes and one to REDIS_FOLLOWER_HOST for reads. They are the same class with a different host. Your code chooses which one to use for each request.

Section 7 · redis-cli for the experiments

Look inside Redis from the terminal

redis-cli is the command-line client that comes with Redis. Run it inside a container with docker compose exec <service> redis-cli <command>. It sends the same commands as your app.
